4.  Migración a Firebase
4.1  Configuración segura del proyecto
Las credenciales de Firebase deben almacenarse en variables de entorno (.env) y no deben subirse al repositorio (.gitignore). El repositorio debe incluir un archivo .env.example con los nombres de las variables (sin valores reales) y el README debe explicar cómo obtenerlas desde la consola de Firebase.

4.2  Firebase Authentication
El login simulado de la ES3 debe reemplazarse por Firebase Authentication. Requisitos mínimos:
- Inicio de sesión con email y contraseña usando Firebase Auth.
- El objeto de usuario de Firebase (auth.currentUser) debe exponerse mediante el AuthContext existente, usando onAuthStateChanged para mantener la sesión.
- El cierre de sesión debe usar signOut(auth) de Firebase.
- Las rutas protegidas deben validar la sesión usando el estado de Firebase Auth, no localStorage.
- Los errores de Firebase (contraseña incorrecta, usuario no encontrado, etc.) deben mostrarse al usuario de forma comprensible.

4.3  Firestore como base de datos
Todos los datos que en la ES3 se almacenaban en localStorage deben migrar a Firestore:
- Lectura: getDocs o onSnapshot desde Firestore.
- Escritura: addDoc o setDoc.
- Edición: updateDoc.
- Eliminación: deleteDoc.
- La UI debe mostrar un estado de carga mientras espera la respuesta de Firestore.

4.4  Reglas de seguridad de Firestore
Las reglas de seguridad de Firestore deben estar configuradas para que los datos solo sean accesibles por usuarios autenticados. No se acepta dejar las reglas abiertas (allow read, write: if true).

// Regla mínima esperada:
match /databases/{database}/documents {
  match /{document=**} {
    allow read, write: if request.auth != null;
  }
}

💡	Se valorará positivamente si implementas reglas más granulares (ej: solo el propietario puede modificar sus propios documentos). Esto puede compensar puntos en otros criterios.
